## Context

当前大翻译数据处理把“摘要生成失败”视为执行错误，适合处理 timeout、rate limit 或 provider error 这类技术性问题；但对中国大陆高敏舆情而言，这不是技术故障，而是内容类型与模型策略天然冲突。继续重试不会带来更高成功率，反而会拖垮吞吐和交付稳定性。

本次 change 的重点不是“让模型绕过限制”，而是把敏感内容从普通模型路径中分离出来：提前识别、模板降级、要求人工复核、保留整份任务的可交付性。

## Goals / Non-Goals

**Goals:**
- 在 worker 侧用本地规则识别高风险内容。
- 命中规则时不调用模型，直接写入中性模板摘要和复核标记。
- 保持整份工作簿继续处理，最终仍可导出。
- 让日志和结果清晰表明哪些行被降级、为何被降级。

**Non-Goals:**
- 不尝试规避模型内容安全策略。
- 不引入新的外部审核服务或人工审核后台。
- 不在本次 change 中重新设计分类体系。
- 不改造日报类工作台。

## Decisions

### 1. 敏感内容识别放在 worker 本地规则层
- **Decision:** 使用本地规则集（关键词/模式）对文本进行预判，命中后直接分流。
- **Why:** 这是最快、最稳定、最可控的方案，不依赖额外模型，也不会把敏感文本继续发给上游。
- **Alternative considered:** 先让模型判断是否敏感。被拒绝，因为这仍然会触发同样的限制问题。

### 2. 命中后使用模板摘要而不是空白
- **Decision:** 为敏感行写入中性模板摘要，例如“该条内容涉及敏感公共舆情，建议人工复核”。
- **Why:** 空白会导致文件不可交付，也会让用户误以为系统漏处理；模板能明确告诉用户当前状态。
- **Alternative considered:** 直接跳过并记录日志。被拒绝，因为结果文件会出现缺口。

### 3. 人工复核以显式标记形式体现
- **Decision:** 在任务结果与日志里标注“模板降级 / 人工复核”，并将此类行记为 explainable issue 而非执行失败。
- **Why:** 用户需要知道这不是正常 AI 摘要，而是系统有意识的降级处理。
- **Alternative considered:** 仅在日志里显示。被拒绝，因为用户最终主要看结果文件，不一定回到日志区。

### 4. 敏感命中不算 retry 场景
- **Decision:** 敏感命中不再触发 AI retry 或 provider recovery 路径。
- **Why:** 这类内容不是瞬时错误，重试只会浪费时间。
- **Alternative considered:** 先重试一次再降级。被拒绝，因为没有实际收益。

## Risks / Trade-offs

- **[规则误判，正常内容被降级]** → 初版规则从高置信词开始，宁可保守，不做宽泛模糊匹配。
- **[模板摘要信息量偏低]** → 通过人工复核标记补足，让用户知道需要二次处理。
- **[结果文件新增降级语义后，用户理解成本上升]** → 在 UI 和日志中同步解释“模板降级”的含义。
- **[规则长期漂移]** → 将规则集中在单一模块，后续可以独立维护。

## Migration Plan

1. 新增敏感内容识别与模板降级规则。
2. 在 translation worker 里接入“命中即分流”的执行路径。
3. 扩展结果/日志/诊断展示。
4. 增加回归测试：普通内容继续走 AI，敏感内容改为模板降级。

## Open Questions

- 是否在 workbook 中新增独立“人工复核”列：本次先不改 Excel 结构，优先通过结果文案和 issue/log 暴露。
- 模板文案是否分级：本次先保留 2~3 个稳定模板，避免过早复杂化。
